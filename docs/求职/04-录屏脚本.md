# 录屏脚本 · 3 分钟演示视频

> 目标：让人在 3 分钟内看懂「这是个什么东西、你解决了什么、工程上有多实」。
> 结论先说：**用 Web 端录，不要用手机 App 录**（原因见第 1 节），录 1080p、剪到 2:50–3:00。

---

## 1. 为什么不用手机 App 录

| 问题 | 说明 |
|---|---|
| 现有的 APK 是旧版 | 装机包构建于 11-15，**没有搭配页、恢复码、出视频、发布闭环**——录出来会缺掉最新的一半成果 |
| 重新构建要 EAS 云构建 | 本机 Windows 打不出包（路径长度上限），云构建要登录账号、排队 |
| 等待时间不可控 | 单件试衣 40–70 秒、视频排队最长 25 分钟，手机上没法剪 |
| 面试官无法自己试 | 给个 APK 不如给个能点开的地址 |

**替代方案**：Web 端 + 浏览器设备模拟（390×844）+ 录屏软件。三端同构本身就是卖点，Web 画面和手机一致。

---

## 2. 录制前 15 分钟：准备清单

- [ ] 起服务：`npx expo start --web --port 8081`，浏览器先点一遍所有页面让 Metro 编译完（**第一屏冷启动要 8 秒，别在录制时付这个代价**）
- [ ] 预热数据：打开 `/` 和 `/outfits` 各一次，确认天气 chip 显示温度（不是「天气不可用」）
- [ ] 预生成结果：`/profile` 里至少有 **2 条已完成试穿** + **1 条已完成视频**（录制时不真等生成）
- [ ] 清测试数据：删掉「test」「asdf」这类名字的记录和发布（我的 → 试穿记录 → 删除）
- [ ] 收藏 1 件单品 + 1 套搭配（让「我的」页的统计不是全 0）
- [ ] 风格档案设成「通勤 · 极简」（让搭配页有明确偏好可讲）
- [ ] 窗口设置：设备模拟 390×844、缩放 100%、隐藏书签栏、关掉所有通知
- [ ] 录屏参数：1920×1080 或 1080×2340、30fps、麦克风开（口播）

## 3. 分镜表（总长 2:55）

### 00:00–00:12 · 封面 + 一句话
**画面**：首页灵感流第一张卡片（`/`），缓慢上滑一次。
**口播**：
> 「这是一个 AI 穿搭 App。用户上传一张全身照、选一到三件单品，系统会按上装、外套、下装的顺序逐件叠加上身，最后把结果变成一段动态视频。我用 Expo React Native 一套代码跑三端，后端是 Supabase。」

### 00:12–00:30 · 首页：看灵感（`/`）
**操作**：上滑切换 2 张卡片 → 点右下心形收藏 → 点「试穿同款」跳到试衣页并预选该单品。
**口播**：
> 「首页是满屏的灵感流，上下滑动切换，每张卡片可以直接试穿同款、也可以收藏。这个收藏是本地持久化的，待会能在「我的」里看到。」

### 00:30–01:00 · 搭配页：今天穿什么（`/outfits`，点底栏「搭配」）
**操作**：停留 3 秒让人看清 3 套 → 点「换一批」→ 点右上「调整」打开风格档案抽屉 → 选两个气质 → 保存 → 回到列表。
**口播**：
> 「第二页是搭配推荐。它吃三样东西：衣橱里现有的单品、当天的天气、还有你的风格档案。评分里做了颜色家族、温度档位、气质的加权，所以换一批不是随机洗牌，是换一个组合方向。」
> 「重点是每张卡片右下角有两个直达入口：试穿这套、出视频。用户不需要记住自己刚才看的是哪三件。」

### 01:00–01:45 · 试衣页：整套串行试穿（`/tryon`）
**操作**：点「选择全身照」→（用准备好的图）→ 显示「已上传」→ 点 2 件单品（计数 2/3）→ 点主按钮「依次试穿 2 件」→ **等 8 秒拍进度卡** →（剪辑：时间压缩 8×）→ 出结果。
**口播**：
> 「这里是这个项目最核心的一块。商业试衣模型只吃「一张人像 + 一件衣服」，做不了多件同时上。所以我的做法是串行叠加：第 N 步拿第 N−1 步的结果当作新的全身照传进去。整套试穿不需要新接口，代价是三件大约三分钟、一块二。」
> 「进度卡会明确告诉你现在是第几件、已经等了多少秒，因为等待超过 30 秒人就会以为卡死了。」

### 01:45–02:15 · 结果 + 出视频
**操作**：结果图停留 2 秒 → 点「看背面实物图」展开再收起 → 点「生成穿搭视频」→（剪辑：直接切到已生成视频的播放）→ 视频播 3 秒。
**口播**：
> 「结果出来之后有三个动作。第一，AI 只还原正面，所以背面我给了一个诚实的设计：展示这件衣服的实物背面图，而不是让模型编一个背面。」
> 「第二，一键出视频。提示词是四段公式：动作、运镜、背景、保真约束；结尾强制模型转身、背对镜头定格，这样背后也能看见，而且不用把 5 秒拉到 10 秒，成本不变。」

### 02:15–02:35 · 发布闭环
**操作**：点「发布到首页」→ 抽屉里写一句配文 → 点「发布」→ 按钮变「✓ 已发布」→ 切回首页，看到自己那条。
**口播**：
> 「第三，结果可以直接发布到首页灵感流，并且自动关联这件单品。别人刷到之后点「试穿同款」，也能直接跳到自己的试穿。这样就闭合了「看内容 → 产生内容 → 再被别人看到」。」

### 02:35–02:52 · 我的（`/profile`）
**操作**：缓慢下滑：三宫格统计 → 试穿记录（展示缩略图与「已完成」）→ 收藏 → 界面风格点一套别的（如「夜场黑金」）→ 页面立刻换肤 → 恢复码区块。
**口播**：
> 「「我的」里有全部记录、收藏、和五套主题——换肤是即时生效的，因为颜色、字体、圆角全在主题 token 里，页面代码里没有写死任何颜色。」
> 「最后这一块是恢复码。这个 App 没有账号体系，身份只存在这台设备上，清缓存就丢。所以我补了 12 位恢复码：截图存下来，换设备输进去就能把记录接回来。」

### 02:52–02:55 · 收尾字卡（静态）
**画面**：黑底白字，三行：
```
三个数字：单张试衣 ¥0.4 / 40–70 秒，三件串行 ¥1.2
一条链路：Expo RN → Supabase Edge Functions → Aidge / 通义万相
一个原则：先把失败路径想清楚，再写正常路径
```

---

## 4. 剪辑要点

1. **把等待压掉**：40–70 秒的生成等待用 8×–16× 加速，但**保留进度条数字在变**（证明是真跑，不是 PPT）。
2. **字幕全打**：口播有「¥0.4」「40–70 秒」「1.2」这类数字，字幕必须准确。
3. **不要配过度音乐**：轻的 lo-fi 或干脆不配，人声清楚更重要。
4. **前 5 秒定生死**：封面别放 logo，直接放「人穿上裙子在转身」那一帧。
5. **导出**：H.264 / 1080p / 30fps / 码率 8–10 Mbps，控制在 3:00 以内（超过 3 分钟面试官不会看完）。

---

## 5. 录制翻车与补救

| 现象 | 原因 | 补救 |
|---|---|---|
| 首屏白屏 8 秒 | Metro 冷启动 bundle | 录制前先手动点一遍所有页面预热 |
| 图片不显示 / 转圈 | Supabase 线路抖动（本项目实测过连续 4 次 RST） | 停 10 秒重试；或先截图存好，剪辑时用截图顶替并加注「网络抖动，此为静态截图」 |
| 天气显示「不可用」 | 上游 IP 定位被限流（429） | 已做链式降级 + 1 小时冷却，正常会自愈；录制前刷新一次确认 |
| 生成 60 秒没反应 | 供应商排队 | 直接切到预生成的结果继续录，事后补一句口播「这里实际需要 40–70 秒」 |
| 底栏第 5 个图标被裁 | 老版本的布局 bug（已修） | 确认跑的是当前代码，不要用旧分支录 |

## 6. 如果只有 60 秒（二面 / 快速轮）

只录 3 段，每段 20 秒：
1. **00:00** 首页上滑 → 点「试穿同款」（5 秒讲是什么）
2. **00:20** 试衣页选 2 件 → 进度 → 结果（10 秒讲串行叠加，10 秒讲诚实背面）
3. **00:40** 出视频 → 转身定格那一帧停住（20 秒，收尾说「这就是全部链路」）

**一句话结尾**：「整套东西我一个人做完：前端三端、5 个边缘函数、22 个迁移，成本压到一次试衣四毛钱。」
