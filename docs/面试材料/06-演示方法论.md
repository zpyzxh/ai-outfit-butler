# 求职演示包（一次准备，三种讲法）

> 本文是方法论存档（推导过程较长）。要看「现在用哪些文件、按什么顺序用」，入口见 `00-从这里开始.md`。

> 目标：不重复做三份作品，只做**一套资产**，然后针对前端 / 全栈 / 产品三个岗位写三份讲法。
> 这套东西同时能当简历附件、面试投屏材料、以及你自己复盘的项目总结。

---

## 一、为什么不建议「手机登录 + 录屏讲解」

不是不行，是**现在这个状态下风险太高**：

| 风险 | 事实 | 后果 |
|---|---|---|
| APK 是旧版 | `wdxm/2026-11-15/AI穿搭管家-preview-v2.apk` 打在 11-15，早于整个改版 | 录出来没有搭配页、没有恢复码、没有一键出视频，导航还是溢出那版 |
| 生成慢 | 单张试衣 40–70 秒；视频实测排到过 **25 分钟** | 录屏中会有大段死等，节奏全毁 |
| 网络会断 | 同一台机器实测出现过「连续 4 次请求全部 RST」 | 现场点一下就是「衣橱读取失败」，一次就够尴尬 |
| 面试官没法试 | 只有视频 | 少了「他自己点两下」的说服力 |

结论：**主交付用预录，辅交付给一个公网能点的链接**，手机录屏只作为素材来源之一。

## 二、统一资产（只做一次）

### A. 主视频：3 分 00 秒，四段

| 时间 | 画面 | 你做什么 | 字幕/角标 |
|---|---|---|---|
| 0:00–0:15 | 首页满屏灵感卡 | 上下滑两屏，停在连衣裙 | 「看灵感」 |
| 0:15–0:35 | 搭配页三套搭配 | 点「换一批」一次，再点开风格档案选「通勤」 | 「3 套/次，基于衣橱 + 天气 + 风格档案」 |
| 0:35–1:05 | 点某套的「出视频」 | 进入试衣页，展示 `2/3` 与顺序胶囊 | 「一次点击，串行叠加成套」 |
| 1:05–1:40 | 试穿结果 + 视频播放 | 播放一次；展示背面定格 | 「8× 加速，实际约 70 秒」+「结尾定格背面」 |
| 1:40–2:10 | 「发布到首页」→ 首页出现自己的作品 | 点发布、写一句配文 | 「一键发布，带单品关联」 |
| 2:10–2:30 | 我的页：19 条记录、恢复码、收藏搭配 | 划一下列表 | 「私有存储 + 签名 URL」「恢复码跨设备」 |
| 2:30–3:00 | 架构图（技术纸） | 口播技术亮点 | 三个数字：3.8s / 70s / ¥0.4 |

录制要点：
- **真机录屏**（可信度最高）+ 桌面端 390×880 补拍清晰特写，两路素材剪一起。
- 等待段必须加速，并且**如实标注倍数**——这比剪掉更专业。
- 全程不要出现浏览器地址栏、不要出现报错、不要出现你的个人信息（先清测试数据）。

### B. 公网 Web demo（一次导出，永久可用）

```bash
npx expo export --platform web
# 产物在 dist/，扔到 Vercel / Netlify / GitHub Pages 即可
```

为什么值得做：面试官点开就是一个真 App（手机浏览器打开就是手机 UI），比视频有说服力。
安全上没问题——bundle 里只有 anon key，而 RLS 已经按 `owner_user_id = auth.uid()` 收口过了。

### C. 一页技术纸（A4 单页，或 4 页 PDF）

一页打完：
1. 架构图（App → Edge Functions → Aidge/万相 → Supabase Postgres+Storage）
2. 三个「我踩过并修掉的坑」（见下方讲法里挑，不同岗位挑不同的）
3. 一张量化表：Chat 3.8s / 试衣 40–70s / 视频 70s–25min / 单张试衣 ¥0.4 / 三件套 ¥1.2
4. 一句话取舍：「为什么砍掉对话 Tab」

### D. Demo 模式（强烈建议，1 小时工作量）

`EXPO_PUBLIC_DEMO=1` 时：
- `fetchGarments` / `fetchHomeInspiration` 返回本地 fixtures；
- `createTryonTask` / `createVideoTask` 返回预置结果（带 5 秒假进度）；
- 上传走本地 objectURL，不请求网络。

价值：录屏一遍过、面试官随便点都不穿帮、网络挂了也能演。**这是投入产出比最高的一项。**

## 三、三份讲法（同一套画面，三种重心）

### 讲法 1：前端岗（2 分 30 秒）

**重心：设计系统、跨端一致性、可维护性。不主动讲 AI。**

| 段落 | 口播 | 画面 |
|---|---|---|
| 开场 15s | 「这是一个 Expo + React Native 的穿搭 App，同时跑 iOS/Android/Web。我先把 UI 从'功能页'重做成了一套设计系统。」 | 首页 |
| 主题系统 40s | 「5 套主题（时装白/纸感画报/冷灰水泥/夜场黑金/宋式留白），不是换色，是把 **card / button / chip / nav / type** 全部 token 化：间距、圆角、字重、阴影都在主题里定义，页面只消费 token。」 | 我的 → 界面风格，连点四套 |
| 布局坑 35s | 「底栏是浮动胶囊。原来用 `position:absolute + left/right` 写，RN-web 下 `right` 不生效、宽度仍按 100% 算，第 5 个 Tab 直接被挤出屏幕。改成自己算 `width = windowWidth - 2*gutter` 才对。」 | 底栏 5 个 Tab |
| 组件抽象 30s | 「搭配卡片的拼贴：1/2/3 件要三种排布。第一版用 `width:100% + flex` 混写，RN-web 下第一张图占满整行、其余挤成 0 宽。改成纯 flex 比例（`flex:1.5 / flex:1`）才跨端一致。」 | 搭配页三张卡 |
| 细节 20s | 「空态、骨架屏、错误态都是组件化的；错误文案统一走 `toUserMessage()`，不会把 `TypeError: Failed to fetch` 这种英文抛给用户。」 | 断网状态（可先关代理制造） |
| 收尾 10s | 「整体思路是：先定 token，再定组件，最后才是页面。」 | 技术纸 |

**可能被追问**
- Q：为什么不用现成 UI 库？→ 时尚类 App 的排版是产品的一部分，现成库的默认间距/字重会立刻显出"模板感"；token 化之后 5 套主题只换一份配置。
- Q：Web 和原生怎么保证一致？→ 只用 RN 核心组件 + 少量 `Platform.select`；渐变这种 Web 独有的降级成纯色，不引第三方。
- Q：性能？→ 首页是分页 `FlatList`，`initialNumToRender=1 / windowSize=3 / removeClippedSubviews`，同一时刻只有一张视频在播（`focused && appActive && index === activeIndex` 三重门控）。

### 讲法 2：全栈岗（3 分钟）

**重心：链路、数据边界、失败路径、成本。**

| 段落 | 口播 | 画面 |
|---|---|---|
| 链路 30s | 「一条完整链路：上传全身照 → 私有桶 → Edge Function 签 URL → Aidge 试衣 → 结果转存 → 万相图生视频 → 客户端轮询。」 | 架构图 |
| 安全 40s | 「一开始 `tryon_tasks` 对 anon 是全表可读可删，公开桶还能被列举出所有人的照片。我用两个匿名账号做对照实验证明了这个洞：B 能往 A 的目录上传、能删 A 的文件、未登录能 list 出 `garment-1-1536.jpg`。修完之后同样的探针全部 403。」 | 前后对比表 |
| 数据边界 35s | 「照片桶改成私有后，客户端拿不到直链，所以加了一层签名：库里存规范地址，只在实际展示和发给函数那一次换成 1 小时签名 URL，带缓存和并发去重。」 | 我的页缩略图 |
| 失败路径 40s | 「最典型的一个 bug：试衣接口是**同步**的，要等 40–70 秒；我给客户端设了 20 秒超时 —— 用户看到'生成失败'，服务端却照跑照扣费。教训是**同步生成型接口的超时必须 ≥ 供应商上限**，异步轮询型才该给短超时。」 | 代码片段 |
| 成本 20s | 「单张试衣 ¥0.4，三件套 ¥1.2；一次视频 5 秒约 ¥0.3。所以配额必须按次扣，不能给'无限次'套餐。」 | 成本表 |
| 收尾 15s | 「这个项目我最大的收获是：**先把失败路径想清楚，比先把功能做完更重要**。」 | 技术纸 |

**可能被追问**
- Q：为什么用匿名登录？→ 产品定位是"打开就能用"，不强制注册；代价是身份跟设备绑定，所以补了 12 位恢复码（服务端只存 SHA-256 哈希，RLS 不开放该表、只能走 definer 函数）。
- Q：怎么防止重复扣费？→ 幂等键 + 状态机；现状是「客户端超时但服务端继续跑」，下一步是把状态流转做成 CAS（`claim_tryon_task` / `finish_tryon_task`），已在路线图里。
- Q：多供应商怎么解耦？→ 抽象出 `VideoProvider{submit,poll}`，`provider_task_id` 加前缀（`ark:` / `kling:` / `ds:`），无前缀视为 legacy。

### 讲法 3：产品岗（2 分 30 秒）

**重心：用户旅程、信息架构决策、留存钩子、单位经济。**

| 段落 | 口播 | 画面 |
|---|---|---|
| 定位 20s | 「一句话：帮用户把'看到一件喜欢的衣服'变成'看到自己穿上的样子'，再变成'能发出去的动态'。」 | 首页 |
| IA 决策 40s | 「第一版底栏是：首页 / **对话** / 发布 / 试衣 / 我的。我做了一个判断：对话类功能依赖的外部模型服务当时不可用，它却占着最贵的入口位。所以把'搭配'提上来，对话降级到搭配页底部的入口 —— **功能没删，只是降级**。」 | 底栏前后对比 |
| 降低门槛 35s | 「试衣的原始流程是'选一件 → 等 70 秒 → 再选一件'。我把它改成一次选 1–3 件，**串行叠加**，中途能看到第 1/3、2/3 的进度；再进一步，搭配页上直接一个'出视频'，一次点击跑完成套。」 | 试衣页 2/3 |
| 价值放大 30s | 「生成完不是终点。结果图可以一键发布到首页，并自动关联那件单品 —— 别人点进去就能'试穿同款'，这就形成了内容→转化的闭环。」 | 发布 → 首页 |
| 单位经济 25s | 「成本结构：试衣 ¥0.4/张，三件套 ¥1.2，视频 ¥0.3/条。定价 10 次 ¥9.9，毛利大概 60%，所以免费额度不能给大。」 | 成本表 |
| 反思 20s | 「最大的坑是我一开始没分清'匿名身份'和'用户账号'：用户清个缓存，历史就没了。后来用恢复码补上——**这类'看起来是 bug，其实是产品设计缺口'的问题最容易被忽略**。」 | 恢复码 |

**可能被追问**
- Q：为什么不做社区首页优先？→ 冷启动没有内容，瀑布流会空。所以先做「衣橱 + 搭配引擎」保证单机可用，社区是第二层。
- Q：留存靠什么？→ 三段钩子：每日搭配（有新鲜感）→ 试穿记录（沉没成本）→ 收藏（回访理由）。
- Q：为什么不收会员费？→ 单次成本是变动的（按次计费），会员制意味着无限次被滥用；先按次卖。

## 四、高频追问防御清单

1. **「这是你自己做的吗？」** → 直接打开 commit 历史 / 迭代报告 `docs/迭代报告-2026-11-16.md`（30 节，每节都有"为什么做 + 怎么验证"）。
2. **「AI 部分是你调的吗？」** → 讲提示词公式（运动 + 运镜 + 背景 + 保真约束）和「单向转身」的设计——为什么不做"转过去再转回来"（脸会崩、且要多花 5 秒）。
3. **「遇到最大的 bug？」** → 同步接口超时错位（用户看到失败、服务端照扣费），一句话讲清"症状 / 根因 / 修法 / 教训"。
4. **「怎么保证安全？」** → 用"我做了对照实验"这个说法，比背 RLS 概念有说服力。
5. **「为什么不用 X 框架/云服务？」** → 给取舍理由，不要贬低其他选项。
6. **「性能怎么样？」** → 首页单视频播放、列表批量签名、图片 2049px 上限。
7. **「如果给你三个月？」** → 幂等状态机 → 多 provider → 整套试穿的后端化（advance-on-request）→ 姿态驱动视频。
