## 1. 任务状态机与幂等（P1，钱和数据的正确性）

### 1.1 现状问题

| 位置 | 问题 |
|---|---|
| `functions/tryon/index.ts:236-271`、`456-478` | Aidge 同步调用 ~56s，无幂等键、无任务占用，客户端重试即重复计费 |

| `functions/video/index.ts:150-154` | 重复提交守卫是 TOCTOU，且不挡 `done` → 并发双扣费 / 覆盖已付费视频 |
| `functions/video/index.ts:213-227` | 视频阶段 UPDATE 不解构 error → 任务永远卡 `tryon/processing` |
| `009_entitlements.sql:11-15` | `tryon_tasks` 没有 `entitlement_id` → 轮询阶段失败无法退款 |

### 1.2 改法

```sql
-- 015_task_state_machine.sql
alter table public.tryon_tasks
  add column if not exists idempotency_key text,
  add column if not exists entitlement_id uuid,
  add column if not exists refunded_at timestamptz,
  add column if not exists provider_status text;

create unique index if not exists tryon_tasks_idem_idx
  on public.tryon_tasks (owner_user_id, idempotency_key)
  where idempotency_key is not null;

-- 原子占用：只有从 pending 抢占成功的那一个请求才真正调用供应商
create or replace function public.claim_tryon_task(p_task_id uuid)
returns boolean language sql security definer set search_path = public as $$
  update public.tryon_tasks
     set status = 'processing', stage_started_at = now()
   where id = p_task_id and status = 'pending'
  returning true;
$$;

-- 原子终态：只有 processing 才能进终态，杜绝 timeout 覆盖 done
create or replace function public.finish_tryon_task(
  p_task_id uuid, p_status text, p_first_frame_url text default null,
  p_result_url text default null, p_error text default null
) returns boolean language sql security definer set search_path = public as $$
  update public.tryon_tasks
     set status = p_status,
         first_frame_url = coalesce(p_first_frame_url, first_frame_url),
         result_url = coalesce(p_result_url, result_url),
         error_msg = p_error
   where id = p_task_id and status = 'processing'
  returning true;
$$;

revoke all on function public.claim_tryon_task(uuid) from public, anon, authenticated;
revoke all on function public.finish_tryon_task(uuid,text,text,text,text) from public, anon, authenticated;
```

客户端已经用 `x-device-id` 调 `createTryonTask`，让它在 body 里再带 `idempotency_key`（前端可用 `deviceId + garmentId + 时间戳分钟`），服务端命中唯一索引时直接返回既有任务，不再调用供应商。

退款函数（失败/超时都要调用）：

```sql
create or replace function public.refund_entitlement_once(p_task_id uuid, p_reason text)
returns boolean language plpgsql security definer set search_path = public as $$
declare v_ent uuid;
begin
  select entitlement_id into v_ent
    from public.tryon_tasks
   where id = p_task_id and refunded_at is null
   for update;
  if v_ent is null then return false; end if;

  update public.entitlements set remaining = remaining + 1 where id = v_ent;
  update public.tryon_tasks set refunded_at = now(), error_msg = coalesce(error_msg, p_reason) where id = p_task_id;
  return true;
end $$;
```

### 1.3 另外三处必须改

1. **非 JSON 响应**：`tryon:672`、`video:204/278`、`chat:143` 的 `res.json()` 抛错会被顶层 catch 原样吐给客户端 → 先 `await res.text()`，再 `try/catch JSON.parse`，对外统一 `{ error: '上游服务暂时不可用' }`。
2. **结果下载**：`tryon:635-641`、`video:296-300` 的 `arrayBuffer()` 全量进内存且无超时 → `AbortSignal.timeout(20_000)`，并限制 `content-length`（>20MB 直接失败）。
3. **转存失败**：`tryon:654-663` 现在静默降级到供应商临时链、任务照标 done → 应标 `failed` 并退款（临时链 24h 就失效，历史记录必然裂图）。

## 3. 整套试穿后端化（P2，体验上限）

Aidge 单件同步 56s，Edge wall clock Free 150s / Pro 400s → 串行 3 步必超时。改成 **advance-on-request**：

```
POST /tryon {user_photo_url, outfit_items:[...], step_total:3}  → 只跑第 1 步
     ← {task_id, status:"step_done", step_index:0, step_total:3, preview_url, next_action:"advance"}
POST /tryon {action:"advance", task_id}                          → 跑第 2 步
     ← {status:"step_done", step_index:1, ...}   /   {status:"done", result_url}
```

落库：

```sql
alter table public.tryon_tasks
  add column if not exists source_type text default 'single',   -- single | outfit
  add column if not exists parent_task_id uuid,
  add column if not exists step_index int default 0,
  add column if not exists step_total int default 1;

create table if not exists public.outfit_items (
  id uuid primary key default gen_random_uuid(),
  task_id uuid not null references public.tryon_tasks(id) on delete cascade,
  step_index int not null,
  garment_id uuid not null references public.garments(id),
  input_url text not null,
  output_url text,
  status text not null default 'pending',
  created_at timestamptz not null default now()
);
```

**质量缓解**（多步叠加必然逐次失真，必须做）：
- 每步归一画布（把输入图统一 resize 到 1536×2048 的固定框内、保持人物占比）；
- 头部 18% 区域回贴，防止"换脸"；
- 中间结果存 **PNG** 而非 JPEG，减少累积压缩损失；
- 提供 `retry_step`（只重跑某一步，扣 1 次配额）。

**成本**：Aidge 约 ¥0.40/件 → 两件套 ¥0.80、三件套 ¥1.20，已经高于 `tryon_10` 单次收入 ¥0.99。所以必须**按步扣配额**，并把套餐文案改成「1 次配额 = 1 件试穿」。

## 4. 配额与计费（P1）

- `payment/index.ts:35-39` 的 `monthly` 套餐 `quota: null` = 无限次，配合 `/video` 完全不扣权益 → 一台设备一天可跑 432 次（约 ¥172 成本 vs ¥29.9 收入）。至少给 monthly 加日上限（如 30 次/日），`/video` 必须扣 1 次。

## 6. 定时收敛（P2）

用户关掉 App 就没人轮询，`processing` 任务会永远卡住（前端 15 分钟兜底也只在页面开着时生效）。

```sql
-- 每分钟：把超过 20 分钟仍在 processing 的任务标 timeout 并退款
select cron.schedule('reap-stale-tasks', '* * * * *', $$
  with stale as (
    update public.tryon_tasks
       set status = 'timeout', error_msg = coalesce(error_msg, '生成超时，请重试')
     where status = 'processing'
       and stage_started_at < now() - interval '20 minutes'
    returning id, entitlement_id
  )
  select 1;
$$);
```

再配一个「查供应商最终状态回填」的 worker（按 `provider_task_id` 前缀分发），能救回"超时但供应商其实成功了"的那批任务。

## 8. 匿名身份迁移（P3）

匿名 uid 是 `owner_user_id` 的来源，登录会换 uid → 历史全部"消失"。两种解法：

- 登录时 `supabase.auth.updateUser({ email })` 原地升级（Supabase 支持匿名用户绑定邮箱，uid 不变）；
- 或登录成功后把 `tryon_tasks.owner_user_id` 批量迁移到新 uid（需要 service_role 函数）。
